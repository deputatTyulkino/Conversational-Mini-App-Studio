# Инструкция по разметке корпуса запросов роутера

## 1. Назначение

Корпус - это набор запросов к чату с ожидаемым ответом роутера. Он нужен для:
обучения модели (dev), подбора порога ASK (dev) и финальной оценки (test).
Метка показывает, что **должен** сделать роутер, а не что «было бы неплохо».

Допущения:
- приложений три: `research_board`, `project_planner`, `data_explorer`; stretch-приложения (Decision Matrix, Learning Map) не делаем;
- запросы на русском; английские термины допустимы («CSV», «дедлайн»), опечатки и разговорный стиль тоже;
- ASK там, где ожидалось приложение, считается ошибкой.

## 2. Главный вопрос разметчика

Метку определяет не тема запроса, а то, **что человек хочет получить в итоге**:

- проверить, чем подтверждены его утверждения -> `research_board`
- сроки, порядок задач, «успею ли», «что сдвинется» -> `project_planner`
- цифры из своей таблицы: фильтр, итоги по группам, «что если» -> `data_explorer`
- совет, объяснение или то, чего платформа не умеет -> `NONE`
- из текста нельзя понять, какое из двух приложений нужно -> `ASK`

## 3. Метки

### `research_board`

**Что хочет пользователь.** Понять, какие из его утверждений подтверждены
источниками, связать утверждение с источником или найти утверждения без опоры.

**Синонимы.**
- утверждение: тезис, аргумент, вывод, факт, мысль в докладе
- источник: ссылка, статья, литература, цитата, исследование
- связь: подтверждает, опирается на, обосновывает, подкрепляет

**Примеры.**
1. «Какие утверждения в моём докладе ничем не подкреплены?»
2. «Привяжи статью Иванова к тезису про сон студентов»
3. «Если я уберу эту статью, какие аргументы останутся без опоры?»

**Похоже, но не research_board.**
- «Как оформить список литературы по ГОСТу?» -> NONE (R2)
- «Найди мне статьи про сон студентов» -> NONE (R8: веб-поиска нет)
- «Посчитай, сколько моих источников вышло за последние 5 лет» -> data_explorer (R4)
- «Помоги выбрать тему курсовой: важнее всего наличие литературы, потом интерес» -> NONE (R10)

**Пограничное.**
- «Разложи мои источники по таблице» -> ASK, candidates: [research_board, data_explorer]

### `project_planner`

**Что хочет пользователь.** Понять, успеет ли он к сроку, в каком порядке
делать задачи и что сдвинется, если задача затянется или поменяется порядок.

**Синонимы.**
- задача: этап, шаг, пункт плана, часть работы
- срок: дедлайн, сдача, защита, «к 20-му числу»
- длительность: «сколько займёт», дни, недели
- зависимость: «сначала… потом», «после того как», «не могу начать, пока…»
- сдвиг: затянется, опоздает, задержится, перенести

**Примеры.**
1. «У меня шесть задач по курсовой, успею ли я до 20 декабря?»
2. «Если вёрстка займёт не 2 дня, а 6, когда мы закончим?»
3. «Пока Петя не нарисует дизайн, я не могу начать фронт. Что будет, если он задержится на неделю?»
4. «В таблице с дедлайнами перенеси срок отчёта на другое число» (R5: цель - срок)

**Похоже, но не project_planner.**
- «Как составить план курсовой?» -> NONE (R2: своих задач не даёт)
- «Напомни мне про дедлайн в пятницу» -> NONE (R8: напоминаний нет)
- «Какой день недели будет 20 декабря?» -> NONE (дата есть, планирования нет)
- «Посчитай по моей таблице, сколько часов в неделю я трачу на учёбу» -> data_explorer (R5)

**Пограничное.**
- «Вот таблица с задачами и датами, разберись с ней» -> ASK, candidates: [project_planner, data_explorer]

### `data_explorer`

**Что хочет пользователь.** Получить цифры из своей таблицы (CSV/JSON):
отфильтровать строки, сгруппировать и посчитать итоги или проверить
«что если», то есть как изменится итог, если часть значений изменится.

**Синонимы.**
- данные: таблица, CSV, JSON, выгрузка, ведомость, строки, столбцы
- подсчёт: посчитай, сумма, итого, среднее, сколько всего
- фильтр: только, без, отбери, оставь, «за февраль»
- группировка: по каждому, по месяцам, по регионам, в разрезе, сравни между
- что если: «а если вырастет на 10%», «если поднять цену», «что будет с итогом»

**Примеры.**
1. «Рассчитай мои баллы за семестр по ведомости»
2. «Составь по табличке отчёт за квартал с итогами по месяцам»
3. «Оставь в таблице продаж только февраль и март и покажи сумму по регионам»
4. «Если продажи на Юге вырастут на 10%, сколько получится всего?»

**Похоже, но не data_explorer.**
- «Стоит ли вести учёт в экселе?» -> NONE (R2)
- «Проверь, есть ли в докладе страницы о литературе» -> NONE (R6)
- «Есть ли в этой пдфке постулаты теории относительности?» -> NONE (R6)
- «Разберись с этой схемой» (картинка, .drawio) -> NONE (R6)
- «Сравни два ноутбука по цене и весу, для меня вес важнее» -> NONE (R10)

**Пограничное.**
- «Вот таблица с задачами и датами, разберись с ней» -> ASK, candidates: [project_planner, data_explorer]
- «Разложи мои источники по таблице» -> ASK, candidates: [research_board, data_explorer]

### NONE и ASK

- `NONE`: ни одно приложение не нужно. Чат отвечает обычным текстом.
- `ASK`: подходят ровно два приложения, и из текста не понять, какое нужно.
  Обязательно поле `candidates` с двумя разными приложениями.

## 4. Правила для спорных случаев

- **R1. Синонимы размечаются так же, как и основные слова.** Синоним («тезис», «дедлайн», «ведомость») размечается так же, как основное слово.
- **R2. Совет - это NONE.** «Как сделать», «что такое», «стоит ли», «объясни» без своих данных пользователя -> NONE, даже если в запросе есть слова из приложений.
- **R3. ASK только при неясной цели.** Сначала найди цель: что человек просит сделать (глагол). Слова из двух приложений - ещё не повод для ASK. ASK ставится, только если цели нет («разберись», «глянь», «помоги с этим») и данные подходят ровно двум приложениям -> `ASK` + `candidates`.
- **R4. Источники.** Цель - проверить подтверждённость утверждений -> `research_board`. Цель - посчитать, отфильтровать или сгруппировать источники по признаку (год, автор, страна, тип) -> `data_explorer`.
- **R5. Задачи.** Цель - сроки, порядок или сдвиги -> `project_planner`. Изменить, перенести или убрать сроки -> `project_planner`, даже если они «в таблице». Цель - суммы, фильтры или сравнения чисел -> `data_explorer`. Цель не названа -> ASK.
- **R6. Документы - не данные.** Текст, доклад, конспект, учебник, PDF, Word, картинки, схемы: найти, прочитать, изменить, пересказать, сделать по ним карточки, тест или карту понятий -> NONE. Data Explorer работает только с таблицами CSV/JSON.
- **R7. «Удали без подтверждения».** Если в запросе есть задача для приложения -> метка этого приложения (чат только открывает его, изменения подтверждаются внутри). Если задачи нет, только команда сломать или обойти правила -> NONE.
- **R8. Чего платформа не умеет** (веб-поиск, напоминания, написание и отправка писем, скачивание файлов) -> NONE.
- **R9. Названия не в счёт.** Слова из названий книг, статей и файлов («Как успевать всё в срок?») на метку не влияют: метку определяет просьба пользователя.
- **R10. Выбор между вариантами.** «Какой ноутбук взять», «сравни магистратуры по критериям», «помоги выбрать тему» -> NONE: приложения для выбора вариантов нет. Сравнить числа из своей таблицы (регионы, месяцы, серии опытов) -> `data_explorer`.

Новое правило добавляется сюда с номером, если при разметке пришлось сомневаться больше одного раза в похожих запросах.

## 5. Типы запросов

| type | Что это | Допустимые label |
|---|---|---|
| positive | ясно, какое приложение нужно | одно из трёх приложений |
| ambiguous | подходят два приложения | ASK |
| unknown | ни одно приложение не подходит | NONE |
| adversarial | создан, чтобы сбить роутер: ключевые слова без нужного смысла, смысл без ключевых слов, попытки обойти подтверждение | любая, по смыслу (R1–R10) |

Ориентир по долям: приложения ~60% (поровну на три), ambiguous ~15%, unknown ~15%, adversarial ~10%.
ASK-пары распределять по разным сочетаниям приложений, а не только по одной паре.

## 6. Формат записи

Файлы `corpus/dev.jsonl` и `corpus/test.jsonl`, одна строка - один JSON-объект, кодировка UTF-8.

| Поле | Обязательно | Значение |
|---|---|---|
| `id` | да | `q0001`, `q0002`…; не меняется и не используется повторно |
| `text` | да | текст запроса как есть, с опечатками |
| `label` | да | `research_board`, `project_planner`, `data_explorer`, `NONE`, `ASK` |
| `type` | да | `positive`, `ambiguous`, `unknown`, `adversarial` |
| `author` | да | псевдоним: `team-1`, `team-2`, `ext-01`…; `gen-claude` для запросов, написанных ИИ-ассистентом; без настоящих имён |
| `candidates` | только при ASK | два разных приложения |

```jsonl
{"id": "q0001", "text": "У меня шесть задач по курсовой, успею ли я до 20 декабря?", "label": "project_planner", "type": "positive", "author": "team-1"}
{"id": "q0005", "text": "Вот таблица с задачами и датами, разберись с ней", "label": "ASK", "type": "ambiguous", "author": "team-1", "candidates": ["project_planner", "data_explorer"]}
{"id": "q0004", "text": "Как оформить список литературы по ГОСТу?", "label": "NONE", "type": "adversarial", "author": "team-1"}
```

При обучении `NONE` переводится в класс `none` (всего четыре класса: три приложения и `none`), запросы с `ASK` в обучение модели не идут и используются для подбора порога на dev.

## 7. Объём, разделение и заморозка

- Весь корпус 150–200 запросов, test не меньше 90.
- В dev не меньше 20 positive-запросов на каждое приложение, иначе кросс-валидация на 5 частей даст по 4 примера класса в части.
- Все внешние запросы (`author: ext-…`) идут в test; они должны составлять не меньше трети test.
- Остаток test добирается из командных запросов случайно, со стратификацией по `label`.
- Перефразировки одного запроса держать в одном файле.
- После заморозки записать SHA-256 файла test в `corpus/test.sha256`. Test больше не открывать до финальной оценки.
- Запросы, разобранные при составлении этой инструкции, идут только в dev.
- Запросы с `author: gen-claude` идут только в dev: test должен показывать, как пишут живые люди.

## 8. Чего не делать

- Не писать запросы, держа в голове ключевые слова: пишите так, как спросил бы обычный студент.
- Не показывать внешним авторам примеры запросов и названия приложений.
- Не дописывать и не менять test после того, как увидели ошибки модели.
- Не подбирать правила роутера (`router/rules.py`) по test.

## 9. Открыто

- Согласованность разметки (Cohen's kappa) проверить на 40–50 запросах вторым разметчиком.
