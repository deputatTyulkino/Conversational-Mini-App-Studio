# Требования: Project Planner


| ID | Тип | Требование | Откуда | Как проверить | Приоритет |
|---|---|---|---|---|---|
| PP-1 | бизнес | Команда заранее видит, успевает ли она к сроку и что сдвинется, если план изменится | ТЗ | Сквозной сценарий с изменением длительности | обязательно |
| PP-2 | бизнес | При срыве срока понятно, какие задачи его вызвали | ТЗ | В каждом конфликте названы задачи | обязательно |
| PP-3 | пользовательское | Изменить длительность задачи и увидеть новый срок окончания | ТЗ | Сквозной сценарий | обязательно |
| PP-4 | пользовательское | Добавить или убрать зависимость между задачами | ТЗ | Сквозной сценарий | обязательно |
| PP-5 | пользовательское | Задать срок проекта и срок отдельной задачи | предложение | Сквозной сценарий | обязательно |
| PP-6 | пользовательское | Увидеть цепочку задач, которую нельзя затягивать | предложение | Такие задачи выделены на плане | желательно |
| PP-7 | пользовательское | Вернуть итог планирования в чат | ТЗ | Сквозной сценарий | обязательно |
| PP-8 | функциональное | План открывается из чата по запросу через общий реестр приложений | ТЗ | Запрос «успею ли я до 20 декабря» открывает план | обязательно |
| PP-9 | функциональное | Задачи показаны на шкале времени, зависимости нарисованы связями | ТЗ | Renderer принимает схему экрана | обязательно |
| PP-10 | функциональное | После изменения длительности или зависимости расписание пересчитывается сразу | ТЗ | Срок окончания меняется без перезагрузки | обязательно |
| PP-11 | функциональное | Приложение находит конфликты и называет задачи, которые в них участвуют | ТЗ | Три размеченных учебных плана, по одному на конфликт | обязательно |
| PP-12 | функциональное | Конфликтов три вида: проект не укладывается в срок, задача не укладывается в свой срок, зависимости замкнулись в цикл | предложение | Те же три учебных плана | обязательно |
| PP-13 | функциональное | При цикле в зависимостях приложение не показывает срок окончания и называет задачи цикла | предложение | Учебный план с циклом | обязательно |
| PP-14 | функциональное | Удаление задачи, сдвиг нескольких задач разом и выгрузка плана требуют подтверждения | ТЗ | Без подтверждения план не меняется | обязательно |
| PP-15 | функциональное | Каждое подтверждённое и отменённое действие попадает в журнал | ТЗ | В журнале есть запись и об удалении, и об отмене | обязательно |
| PP-16 | функциональное | Итог в чате называет срок окончания, цепочку задач без запаса времени и оставшиеся конфликты | ТЗ требует итог, состав предложен | Итог совпадает с тем, что на плане | обязательно |
| PP-17 | нефункциональное | Один и тот же план всегда даёт один и тот же расчёт | предложение | Повторный расчёт даёт тот же результат | обязательно |
| PP-18 | нефункциональное | Есть учебные планы, с которыми приложение работает без сети | ТЗ | Сценарий проходит без интернета | обязательно |
| PP-19 | нефункциональное | Два сквозных сценария проходят целиком, в каждом пользователь что-то меняет и возвращает итог в чат | ТЗ | Отчёт evaluator | обязательно |
| PP-20 | ограничение | Время считается в условных днях от начала проекта. Календаря, выходных и исполнителей нет | предложение | | решить |
| PP-21 | ограничение | Совместного редактирования в реальном времени нет | ТЗ | | обязательно |
| PP-22 | ограничение | Напоминаний о сроках нет | предложение | Запрос «напомни про дедлайн» план не открывает | обязательно |

## Что осталось решить

1. Откуда берётся исходный план: пользователь вводит задачи руками, приложение разбирает текст запроса или открывает готовый учебный набор.
2. В каких единицах считается время (PP-20). В таблице предложены условные дни, пользователю могут понадобиться даты.
3. В каком формате выгружается план.
